Usage: kling image_to_video [--image <url|path> | --input <name>=<url|path>] [options] [prompt]
Client options:
  --image            Reference image URL or local path (repeatable; local files auto-uploaded)
  --tailImage        Tail-frame image URL or local path (fills the model's declared tail slot)
  --input            Fill one declared input slot as <name>=<url|path> (repeatable), e.g.
                     --input tail_image=./last.png. Slot names come from `kling who_am_i`;
                     use it to address keyframes in any position. Not combinable with
                     --image / --tailImage.
  --model            Model name (required; from `kling who_am_i`)
  --poll             Wait up to N seconds for results before returning (0=off; bare flag=60)
Generation parameters (declared per model by the server — see `kling who_am_i`):
  any --<name> the model declares, snake_case or camelCase.
Prompt is optional when the chosen model declares it optional; frames are optional when the
model declares every frame slot optional. The server validates the submitted input combination.

MCP tool: image_to_video

Description:
Animate one or more images into a video with Kling AI. Call who_am_i first to discover the available models, each model's argument specification, and its required inputs. Input URLs must either be links returned by the file_upload tool for local uploads, or publicly accessible external file URLs. Supported image specs: PNG/JPG only, below 4K resolution, ≤30MB, aspect ratio no wider than 1:2. URLs generated by prior Kling tasks can be used directly without downloading or validation. Returns a generation_id immediately; poll query_tasks for the result. - If user intent or any parameter is uncertain, ask first. Every job is charged; do not submit trial jobs.- If user uses alias words, map to canonical names and pass canonical only. Do not invent names or value.- On timeout/long hang/failure/unexpected result, keep user informed. Ask user whether to retry or change parameters. Do not auto-resubmit or silently change intent/parameters. Image subjects (cover + secondary) may be bound when this model's who_am_i lists 'elements'. Video subjects (resource.video) may be bound only on kling-video-v3_0_omni or kling-video-v3_0, not on kling-video-o1. Do not discard the element‑id and fall back to only using its cover image or text description as generation parameters, unless the user explicitly requests this behavior. Pass the original element‑id while cover image and text‑related information can be supplied as auxiliary parameters to improve generation quality. Constraint: A task with no image and no element, only a prompt, must use the text_to_video tool rather than image_to_video.
