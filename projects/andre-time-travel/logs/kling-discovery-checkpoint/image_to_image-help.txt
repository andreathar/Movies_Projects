Usage: kling image_to_image --image <url|path> [--image ...] [options] <prompt>
Client options:
  --image            Reference image URL or local path (repeatable; local files auto-uploaded)
  --model            Model name (required; from `kling who_am_i`)
  --poll             Wait up to N seconds for results before returning (0=off; bare flag=60)
Generation parameters (declared per model by the server — see `kling who_am_i`):
  any --<name> the model declares, snake_case or camelCase.
Prompt may reference inputs as image 1/image N per the model's input declaration.

MCP tool: image_to_image

Description:
Generate new images or edit images from reference image(s) and a text prompt with Kling AI. Call who_am_i first to discover the available models, each model's argument specification, and its required inputs. Input URLs must either be links returned by the file_upload tool for local uploads, or publicly accessible external file URLs. Supported image specs: PNG/JPG only, below 4K resolution, ≤30MB, aspect ratio no wider than 1:2. URLs generated by prior Kling tasks can be used directly without downloading or validation. Returns a generation_id immediately; poll query_tasks for the result. - If user intent or any parameter is uncertain, ask first. Every job is charged; do not submit trial jobs.- If user uses alias words, map to canonical names and pass canonical only. Do not invent names or value.- On timeout/long hang/failure/unexpected result, keep user informed. Ask user whether to retry or change parameters. Do not auto-resubmit or silently change intent/parameters. Image-subject binding: image_to_image CAN bind image subjects (cover + secondary, no resource.video) on every model that lists 'elements', INCLUDING kling-image-o1. Never refuse an image-subject request just because the model is kling-image-o1. Video-subject binding: image_to_image CANNOT bind video subjects. If element_get shows resource.video, tell the user first and use image_to_video with kling-video-v3_0_omni or kling-video-v3_0 instead. Do not discard the element‑id and fall back to only using its cover image or text description as generation parameters, unless the user explicitly requests this behavior. Pass the original element‑id while cover image and text‑related information can be supplied as auxiliary parameters to improve generation quality.
