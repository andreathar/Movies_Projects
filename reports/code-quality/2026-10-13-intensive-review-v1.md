# Intensive code quality review — 2026-10-13

Reviewed the current Movies_Projects checkout and the uncommitted changes in `sites/movies-demandas`. Eight concrete defects were reproduced with synthetic fixtures: two P1 and six P2. Source code was not repaired during this review. Companion evidence: `2026-10-13-intensive-review-v1.json` in this folder.

P1 means a risk of losing originals or submitting content outside the exact release. P2 means a correctness, integrity or availability defect that should be fixed in the next implementation scope. These are local review findings; no production approval, provider charge or artistic acceptance is inferred.

1. **F01 / P1 — The runner can upload different bytes from the approved reference.** `scripts/kling_batch.py:271` authorizes the fingerprint, then performs discovery and account calls, and eventually gives the CLI mutable local paths at line 315. The film lock serializes runner processes but does not lock image editors or other writers. Reproduction: start from a real synthetic per-job release, modify the reference inside a mocked preflight, and let the remaining runner flow continue with mocked account/provider calls. The result was `SUBMITTED`; the fake provider read the changed bytes; recomputing the fingerprint no longer matched the release. The intent still recorded the earlier fingerprint. Resolve this by binding uploads to immutable, hash-verified snapshots, rechecking the release and its expiry immediately before submission, and refusing any change. A final hash check alone narrows the race but does not eliminate changes during the CLI's later file read. Add a regression covering mutation during discovery/account work and the final upload read.

2. **F02 / P1 — Gemini output silently replaces an existing original.** `scripts/gemini_generate.py:79` opens the requested path with `wb` after generation. There is no existence, symlink or source-overlap rejection. Reproduction: supply an existing temporary output with preserved bytes and mock the Gemini response; the existing bytes were replaced with the synthetic response. If `--output` matches a reference, that reference can also be destroyed. Resolve output safety before any provider call, reject existing files and source overlap, and use exclusive publication so a concurrent file creation cannot be overwritten. This helper also has no scoped release/provenance mechanism comparable to the Kling runner; its network path was not exercised.

3. **F03 / P2 — Imported packages can carry a stale content fingerprint.** `sites/movies-demandas/lib/model.ts:43` validates source hash formats and cross-links but never recomputes `provenance.contentVersion`. The API uses this schema for imports; the bundled-file checker is a separate path. Reproduction: change `approvals.storyboard` to true in a copy of the current package, preserve the original fingerprint, then parse and import it. Both operations succeeded, storing the altered flag under a fingerprint that no longer described the package. This does not mutate the canonical film approval, but it makes the displayed projection and audit identifier disagree. When provenance is present, recompute and compare the package digest on client preview and server import. Continue to describe it as an integrity checksum, not proof of a director's identity; a recomputed hash is not authentication. Legacy packages without provenance need an explicit compatibility policy.

4. **F04 / P2 — Official-task dependency validation has exponential cost.** `sites/movies-demandas/lib/model.ts:54` traverses shared descendants repeatedly without a completed-node cache; `validateTask` has a similar traversal. Reproduction: use an acyclic graph in which each task depends on the next two tasks, remove unrelated optional plan/workflow data, and parse in a bounded child process. Eighteen tasks parsed in 13 ms; both 30 and 38 tasks exceeded a 2,000 ms process limit and were terminated. The allowed package limit is 200 tasks. Import preview parses on the browser thread and the API repeats parsing, so an ordinary valid graph can stall either path. Use a node map and separate visiting/completed sets, giving O(V+E) traversal. Test a branching DAG with shared descendants, not only a chain and a cycle.

5. **F05 / P2 — The offline plan validator accepts a duration that truncates the timeline.** `scripts/production_plan.py:407` computes the timeline end but never compares it with `pilot.durationSeconds`. Audio is checked against the timeline end, whereas `scripts/build_galileo_animatic.py:88` trims and exports using the separately declared pilot duration. Reproduction: change only the copied pilot duration from 16 to 5; validation returned an empty errors list while the timeline still ended at 16. A renderer using that accepted plan would cut the response and reaction at five seconds. The frontend schema already rejects this mismatch, so the Python and frontend contracts disagree. Require finite positive durations and exact agreement within frame/timing tolerance before rendering, then validate audio and motivated reactions against the actual export window.

6. **F06 / P2 — The A/B total ceiling excludes the Turbo charge.** `sites/movies-demandas/lib/model.ts:52` compares only `creditsConsumed` with `totalCeiling`, while the next condition checks Turbo only against its individual cap. Reproduction: retain the recorded 27 + 24 charges, set the total ceiling to 40 and Turbo's individual cap to 30. `packageSchema.safeParse` succeeded even though the combined charge was 51. Check the sum of every executed job against the total ceiling and retain each individual-cap check. This is a metadata-validation defect; the reproduction neither spends credits nor establishes the meaning of a live account price.

7. **F07 / P2 — Full-snapshot history eventually prevents further imports and work.** `sites/movies-demandas/lib/model.ts:137` retains every complete package in the same state object. `app/api/workspace/route.ts:35` rejects states above 1,800,000 bytes. There is no history compaction/pruning action, and exporting or archiving tasks does not free the retained imports. Reproduction: initialize from the current package, then apply distinct synthetic revisions in memory. Initial state: 87,963 bytes. The 21st additional import produced 22 retained packages and 1,803,065 bytes; the route's size check would reject that import. The last persisted state remains below the limit, so it is inaccurate to say the rejected write is saved; the issue is that new imports remain blocked and ordinary tasks/comments/history further consume the same limited state. Store versions separately, retain bounded deltas/summaries, or provide a safe archive/compaction action that preserves the current package and required audit records.

8. **F08 / P2 — Zero-face coverage accepts invalid or obsolete inspection logs.** `.claude/hooks/zero-face-gate.py:44` accepts any neighboring filename without parsing it; its other branch matches a filename or suffix without comparing hashes or inspection coverage. Reproduction: an adjacent `zero-face-log.json` containing invalid JSON was accepted. Separately, a QC record listing the clip with an all-zero wrong hash and zero inspected frames was accepted. Therefore the hook can allow a reviewed-media delivery without valid evidence for that version. Require parseable structured entries, exact normalized paths, matching media hashes and the required frame/reflection coverage fields. This would check evidence consistency; it still could not authenticate that a human really performed the inspection.
