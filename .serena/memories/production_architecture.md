# Canonical production navigation

Authority: `AGENTS.md` (imported by `CLAUDE.md`) and its linked procedures. This index grants no permission. Read current records at task start; do not infer production truth from a memory, derived package, report, or successful test.

- `workspace.json` selects the film and canonical `productionPlan`, `manifest`, `tasks`, and `state` paths. `scripts/manage.py` implements status/validation/lint/resume and handoff checks; only producer ingestion reconciles deliveries. `docs/LOCAL_AGENT_HANDOFF.md` defines hashes, scope, concurrent-edit preservation, supersession, and producer ownership.
- `projects/<film>/05_storyboard/source/production-plan.json` owns shot/reference proposals. `scripts/production_plan.py` validates/export-pins source versions and exact approval evidence. `docs/PRODUCTION_PLAN.md` defines separate proposal/technical/director/incorporation states. The per-image local review route preserves hash-bound evidence under `00_brief/decisions/image-reviews/`; pending change requests do not become approval, incorporation, or paid release.
- `tasks/board.json` owns task status; `memory/STATE.md` is the short resume surface. `manifest.json`, `00_brief/approvals.json`, `credit-ledger.csv`, asset registry, and decision evidence retain their own canonical subjects. Do not duplicate their volatile contents in Serena. `scripts/kling_release.py`/`kling_batch.py` retain producer-only exact-request release and single-submission gates; image review changes none of those.
- `docs/PARLEY_PROTOCOL.md` defines lane roles and local handoff policy. Parley task/offer/claim/report records coordinate responsibility; reports and ACKs are claims, not director approvals. Handoffs preserve scope/input/output hashes/checks/next owner; producer ingestion and canonical records determine integration. Serena is not a competing task store or coordination lock.
- `.serena/project.yml` deliberately fixes a navigation/read tool set and marks code/memories read-only. Authored notes are updated through reviewed source edits, not lane memory writers. `.gitignore` and explicit exclusions reduce heavy media/cache indexing. This is a tool configuration restriction, not an OS sandbox; no new client grants or service restarts follow automatically.

Frontend boundaries: `mem:frontend_architecture`. Existing commands: `mem:suggested_commands`. Memory links can be checked automatically, but factual freshness requires comparing the relevant current source files after refactors. Keep versioned notes/configuration in the same worktree as the code; one owner edits each note, with hashes and a handoff before integration.
